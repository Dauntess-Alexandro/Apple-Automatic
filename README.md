# 🍏 App Store PPO Automation Control (PRO Mode)

[![Python 3.8+](https://img.shields.io/badge/python-3.8+-blue.svg)](https://www.python.org/downloads/)
[![GUI: PySide6](https://img.shields.io/badge/GUI-PySide6-green.svg)](https://wiki.qt.io/Qt_for_Python)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

**PPO Automation Control** — desktop-приложение для автоматизации работы с **Product Page Optimization (PPO)** и метаданными в **App Store Connect** через официальный API Apple.

Проект ориентирован на iOS-разработчиков и ASO-команды, которым нужно быстро и массово:
- создавать/обновлять PPO-варианты;
- загружать скриншоты в несколько локалей;
- управлять первичной загрузкой метаданных из GUI;
- выполнять AI-assisted генерацию текстов для ASO-полей.

## Основные возможности

### Актуальные модели AITUNNEL

Кнопки **«↻ Модели»** и **«↻ Картинки»** в настройках API читают публичный каталог AITUNNEL. Новые модели больше не блокируются фиксированным списком: для перевода показываются текстовые модели в установленном ценовом лимите, для ТЗ и метаданных — модели с поддержкой изображений. Новые модели картинок показываются выше старых. Сохранённый выбор не меняется.

Обновлены приоритеты и резервный список для работы без каталога: GPT 6 Luna, Claude Haiku 5.5, GPT 6.1 Sol, Grok 4.7, Mistral Large 4, Gemini Nano Banana 2.1, Seedream 5.0 Flash, Flux 3 и другие. Предельная сумма стоимости входа и выхода остаётся прежней: 1200 для перевода и 4000 для метаданных; используется базовая цена за миллион токенов из каталога, а итоговое списание зависит от фактического использования и тарифных уровней провайдера.


### Скриншоты: папка или ZIP → Asset Library → локали

На вкладке **«Скриншоты»** библиотека, порядок изображений и существующие локали находятся прямо внутри вкладки. Отдельное окно для версии и прежние элементы загрузки из файлов/Figma убраны.

1. Нажмите **«Выбрать папку со скринами»** или **«Выбрать ZIP-архив»**. Изображения во вложенных папках тоже учитываются. Перед загрузкой отображается естественный порядок исходных имён: `1.png`, `2.png`, …, `10.png`.
2. Нажмите **«Загрузить в Asset Library»**. Все файлы проверяются по актуальному каталогу Apple до первой отправки; размеры сохраняются, прозрачность сводится на белый фон, метаданные удаляются. Загружаемые копии получают случайные имена вида `a7b93f_001_82ac.png`. Исходные файлы не переименовываются. Превышение лимита группы вызывает ошибку, лишние файлы не пропускаются. После обработки Apple новый набор выбирается в исходном порядке; загрузка сама по себе ещё не меняет локали.
3. Проверьте категорию, порядок и отмеченные существующие локали, затем нажмите **«Назначить скрины и проверить в Apple»**. Те же ассеты переиспользуются во всех локалях. Для разных категорий повторите назначение: результаты нового набора учитываются по категориям и локалям.
4. После подтверждения всего загруженного набора во всех выбранных локалях программа удаляет выбранную папку или ZIP. Ошибка/таймаут, изменение исходников или посторонние файлы в папке сохраняют исходники. Архивы с небезопасными путями и ссылки не принимаются. Общие папки Desktop/Downloads и корень проекта выбирать нельзя — используйте отдельную папку со скринами.

### Назначить уже загруженные скриншоты из Asset Library

1. Откройте вкладку **«Скриншоты»** и нажмите **«Обновить библиотеку и существующие локали»**. Ручная загрузка в Apple также поддерживается; для уже загруженных ассетов локальные исходники не удаляются.
2. Для PPO на вкладке **«Обновить тест»** нажмите **«Взять из Asset Library»**. Этот выбор по-прежнему открывается отдельно. Библиотека и существующие локали читаются в фоне. Показываются существующие ветки всех iOS-версий приложения, включая опубликованную и черновую.
3. Категория определяется по готовности, спецификации и размерам скриншотов из актуального каталога Apple. Если есть совместимые скрины, предпочтение отдаётся **iPhone Dynamic Island — Medium** (например, 1206×2622). Все подходящие изображения сразу добавляются в естественном порядке имён: `1.png`, `2.png`, …, `10.png`. Категорию и порядок можно поменять; **«Убрать»** ничего не удаляет в Apple. Назначается только текущая категория, видимая в окне; при возвращении в другую категорию её порядок сохраняется. Поддерживаются категории iPhone и iPad.
4. Если подходящих изображений больше лимита Apple (обычно 10), есть одинаковые или отсутствующие имена, программа не угадывает набор: выберите нужные изображения вручную. Сверяйте дату загрузки/создания (если Apple её возвращает), размеры, статус и ID. Короткий ID виден в таблице, полный — в подсказке; внутри используется только полный ID. Некорректные/неготовые изображения автоматически не выбираются.
5. Все существующие локали версии отмечаются автоматически. Для PPO сначала выберите конкретную ветку: отмечаются только её существующие локали, другие тесты/ветки не затрагиваются (единственная доступная ветка выбирается сразу). Снимите ненужные отметки при необходимости и подтвердите назначение. Для разных наборов у разных веток повторите операцию с другим выбором. Обычная версия должна быть **iOS** в редактируемом статусе: **Prepare for Submission, Invalid Binary, Rejected, Metadata Rejected или Developer Rejected**; опубликованная версия допускается только при выборе существующих веток PPO. Результаты по локалям появляются после запуска назначения; до нажатия и подтверждения кнопки Apple не изменяется.

Перед изменениями проверяются текущие локали/родительские записи, каталог Apple, разрешённые группы, спецификации, количество, размеры и готовность ассетов. При массовом назначении дерево PPO и список всей библиотеки читаются один раз; перед каждой локалью перечитываются её запись, состояние версии, каталог и только выбранные изображения. Новые локали, тесты и ветки не создаются, трафик и метаданные не меняются. Корректные другие группы, превью и изображения библиотеки сохраняются.

Назначение из Asset Library выполняется параллельно: до **12 локалей одновременно**, с отдельным API-клиентом для каждой локали. Временные сетевые ошибки, таймауты и ответы Apple 429/500/502/503/504 повторяются до **4 попыток** с паузами 1, 2 и 4 секунды, если изменения ещё не начинались или восстановление подтверждено. Неопределённый результат создания размещения требует ручной проверки и не повторяется автоматически. Ход и повторные попытки видны в журнале.

Дополнительная очистка **выключена по умолчанию**: она удаляет только старые размещения других групп с типом `APP_SCREENSHOT`, состоянием `INVALID` и причинами строго `SPEC_MISMATCH` (включая актуальное поле Apple `stateDetails`). Перед удалением кандидат перечитывается с `include=image`. Смешанные/неизвестные причины, корректные размещения и превью не удаляются. Очистка начинается только после успешной проверки назначенного набора; сами библиотечные изображения не удаляются никогда.

Результат показывается **по каждой локали**: подтверждено Apple, ошибка до изменений или ручная проверка. Успех требует совпадения ID, порядка и состояния размещений `ACTIVE`; таймаут или неполное восстановление не считаются успехом. Ошибка одной локали не останавливает остальные. Во время загрузки/чтения/назначения закрытие окна блокируется, чтобы не прервать проверку результата.

Создание и обновление PPO-тестов на соответствующих вкладках сохранены и используют Asset Library. Старый способ отдельной загрузки в каждую локаль из интерфейса недоступен.

### Подготовка скриншотов

Новая загрузка папки/ZIP в Asset Library сохраняет размеры изображений и проверяет совместимость с группами iPhone/iPad по актуальному каталогу Apple. Она не обрезает изображения и не добавляет дополнительные диагонали автоматически. Подготовьте необходимые категории заранее.

Подготовка файлов для создания/обновления PPO сохраняет прежнее поведение: обязательный набор Dynamic Island добавляется отдельной копией, формат и размеры проверяются до отправки. Файлы загружаются один раз и назначаются выбранным локалям через библиотеку. Переключатель старого способа загрузки убран.

[Требования Apple](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications).

- **PPO automation**
  - Создание нового PPO-теста (до 3 вариантов).
  - Обновление существующего теста (варианты/локали выборочно).

- **Параллельная загрузка**
  - Многопоточная загрузка скриншотов (используется `concurrent.futures`).

- **Устойчивость к rate limit**
  - Логика повторов и backoff для сценариев API-ограничений.

- **GUI для metadata**
  - Управление description, keywords, subtitle, promotional text, release notes, app review notes, URL и category-полями.

- **Локальная конфигурация**
  - Работа с `.env` рядом со скриптом (`AuthKey`, `Issuer ID`, ключи интеграций и т.д.).

## Структура проекта

- `app_store_ppo_automation.py` — основное GUI-приложение и бизнес-логика API/валидаций.
- `asset_library.py` — актуальный каталог Apple, однократная загрузка изображений, назначение локалям, проверка порядка и восстановление размещений.
- `asset_library_selection.py` — встроенная библиотека на вкладке «Скриншоты» и общий выбор для PPO, порядок, фоновые операции и результаты по локалям.
- `asset_library_import.py` — чтение папки/ZIP, случайные имена с сохранением порядка, загрузка в библиотеку и проверка исходников перед удалением.
- `requirements.txt` — зависимости Python.
- `Windows_build.bat` — сборка `.exe` через PyInstaller.
- `Mac_build.command` — сборка `.app` через PyInstaller.

## Сборка standalone-приложения

Перед пересборкой закройте все экземпляры `PPO_Automation`: замена файлов открытой сборки может вызвать `Error -3 while decompressing data: incorrect header check` при поздней загрузке модулей. `Mac_build.command` проверяет это до сборки и перед заменой приложения на рабочем столе; неуспешная сборка не устанавливается.

Для проверки подготовки скриншотов внутри готовой macOS-сборки без открытия интерфейса и без обращений к Apple:

```bash
~/Desktop/PPO_Automation.app/Contents/MacOS/PPO_Automation --check-screenshots /tmp/ppo-screenshots-check.json ~/Downloads/*.png
```

JSON-отчёт содержит результат подготовки, размеры и формат каждого файла. Исходники не изменяются; временные файлы удаляются. Код выхода — `0` при успехе, `1` при ошибке, `2` при совпадении пути отчёта с исходником (включая символьные и жёсткие ссылки).

Перед сборкой установите PyInstaller:

```bash
pip install pyinstaller
```

### Windows

```bat
Windows_build.bat
```

### macOS

```bash
chmod +x Mac_build.command
./Mac_build.command
```

После сборки артефакты появляются в папке `dist/`.

## Подготовка App Store Connect API ключа

1. Откройте **App Store Connect → Users and Access → Keys**.
2. Создайте ключ с правами **App Manager** или **Admin**.
3. Скачайте `.p8` файл.
4. Подготовьте:
   - `Issuer ID`
   - `Key ID`
   - `App ID` (числовой Apple ID приложения)
5. Заполните данные в GUI приложения.

## Загрузка билда через GitHub Actions

Во вкладке **Загрузка билда** программа готовит файлы **IOS BUILD**, собирает iOS
и загружает билд в App Store Connect:

1. В **Настройки API** укажите Issuer ID, Key ID и `.p8`. App ID можно оставить пустым:
   программа получит доступные приложения Apple и их Bundle ID.
2. После изменения ключей начинается поиск в `~/Downloads/Projects`. Папку поиска
   можно изменить во вкладке. **Найти и подготовить** повторяет поиск; **Указать проект…**
   позволяет выбрать папку вручную. Совпадение подтверждается Bundle ID из Xcode,
   поэтому переименование папки не мешает. Несколько совпадений требуют выбора.
3. Программа заполняет App ID/Bundle ID и кладёт в корень репозитория
   `github-actions-ios.yml`, `GITHUB_ACTIONS_IOS.md` и рабочий
   `.github/workflows/apple-automatic-ios.yml`. Служебный `.ios-build-files.json`
   позволяет повторять подготовку и защищает ваши ручные правки. Ключи в эти файлы
   не записываются. При простом открытии программы сохранённый проект не изменяется.
4. Отправьте новые файлы вместе с исходниками через GitHub Desktop. При необходимости
   нажмите **Проверить проект**, затем **Собрать и загрузить**: программа настроит
   защищённые ключи GitHub и запустит сборку. Подготовка локальных файлов сама
   ничего не отправляет и не запускает.
5. Для сборки при следующих отправках в основную ветку отметьте соответствующий
   флажок перед запуском **Собрать и загрузить**.

На macOS используется существующий вход в GitHub Desktop. Если доступа нет,
в дополнительных настройках доступен GitHub-токен (только на текущий сеанс).
Fine-grained токену нужны права записи **Contents, Workflows, Actions, Secrets**
в выбранном репозитории. Для classic token нужны `repo` и `workflow`.

Apple-ключ должен разрешать работу с приложением, подписью и загрузкой. Поддерживаются
Flutter iOS проекты с `ios/Runner.xcodeproj` и нативные Swift/Objective-C проекты
с сохранённым `.xcodeproj`, явным Bundle ID и одной общей схемой Xcode. Версия Flutter
по умолчанию 3.47.0. Expo/prebuild, генерация Xcode-проекта и отдельные шаги React Native
требуют настройки workflow под проект; они не добавляются автоматически.

Этапы и результат отображаются во вкладке. Закрытие программы или **Остановить
наблюдение** сохраняют работающую облачную сборку. Вернуться можно кнопкой
**Продолжить наблюдение**; ссылки открывают GitHub и TestFlight. Успешная загрузка
не означает завершение обработки Apple или отправку на App Review.

Каждое приложение сохраняет свой репозиторий и параметры в `.build_upload.json`.
Apple-ключи и GitHub-токен туда не записываются. Собственный файл сборки
`.github/workflows/apple-automatic-ios.yml` привязан к приложению и аккаунту Apple.
Для каждого приложения используйте отдельный репозиторий. Смена Key ID в том же
аккаунте поддерживается: новые секреты не изменяют ключи старых сборок.
Существующий `CERTIFICATE_PRIVATE_KEY` сохраняется; при отсутствии создаётся RSA-ключ
в приватной папке `.build-signing` рядом с конфигурацией программы.


### Переносимый workflow для других типов проектов

Шаблон [`templates/github-actions-ios.yml`](templates/github-actions-ios.yml)
можно скопировать в `.github/workflows/universal-ios.yml` любого репозитория.
Он поддерживает Flutter и нативные Swift/Objective-C проекты, ищет приложение и
общую схему, проверяет Bundle ID/номер билда в IPA и сохраняет файл как `app.ipa`.
[Подключение, секреты и ограничения](docs/GITHUB_ACTIONS_IOS.md).

Это самостоятельный workflow; программа автоматически настраивает рабочий
workflow с привязкой к приложению. Оба исправлены для имён приложений с двоеточием. В генераторе программы
готовый IPA переименовывается перед сохранением в GitHub; подпись и отображаемое
имя приложения сохраняются.
